## 1. サービス概要

**loadline は、Apple Watch に溜まったトレーニングの記録を、アバターが週に1回、声で振り返ってくれる Web サービスです。**

体力、疲労、VO2max の推移を、1つのダッシュボードにまとめます。その前に立ったアバターが、この数週間の流れを、15秒ほどで話します。そのあとに、その週の過ごし方の選択肢が並びます。選ぶのは、本人です。

- **誰の**: 健康のためにランニングや自転車を続けていて、Apple Watch に記録が溜まっている人
- **どんな課題を**: データは揃っているのに、見に行く手間と、読み解く手間のせいで、自分の体に起きている変化と、次に試せることを、見逃している
- **どう解決するか**: 数字を読み解く作業を、アバターが引き受けます。数字を2つか3つ拾い、本人のメモから理由を添えて、励ましを前提に話します。決め打ちのプランは出さず、選択肢を並べます。選んだ結果は、次の週に、一緒に確かめます。

## 2. このアイデアはどこから生まれたか

### 2-1. きっかけとなった体験・感情

きっかけは、X で見かけた記事でした。「VO2max の値と寿命には相関がある」という内容です。

VO2max（最大酸素摂取量）は、運動中に体が取り込める酸素の量の上限です。体重1kg あたり、1分間に何 ml かで表します。心肺機能、つまり持久力の高さを示す、代表的な指標です。Apple Watch を着けて屋外を走ったり歩いたりすると、自動で推定してくれます。測ってみると、私の値は 45〜47 でした。50代後半としては、悪くない数字です。この数字を上げたい。少なくとも、落としたくない。そう思ってから、ロードバイクとランニングを続けながら、VO2max を気にするようになりました。

2026年7月末に、腰痛の治療を受け、その後のケアのためにロードバイクを1ヶ月休みました。再開してから iPhone のヘルスケアを開くと、VO2max がはっきり下がっていました。46.7 あった値が、44.7 まで落ちていたのです。

この結果を見ても、がっかりしませんでした。VO2max とトレーニング量の相関が分かって、面白かったのです。休めば、ちゃんと落ちる。数字と体がつながっていることを実感できて、うれしくさえありました。

同時に、もったいないとも思いました。この面白さに気づけたのは、1ヶ月休むという大きな出来事があって、たまたま数字を見に行ったからです。ふだんは、あまり見ていませんでした。面白い変化は毎週のように起きているはずなのに、見ていないので気づけません。

その少し前、2026年5月の勉強会で、3D のアバターが AI の返事を声で話すデモを見ていました。それを思い出して、考えました。あのアバターがダッシュボードの前に立って、「1ヶ月休んだぶん、VO2max が下がっていますね」と話しかけてきたらどうだろう。同じ数字でも、きっと楽しく見られます。数字を言葉にするのは、LLM の得意なことです。ダッシュボードとアバターと LLM は、相性がいいはずだと思いました。

### 2-2. なぜそれが「気になった」のか

一つは、数字と体の関係が分かると面白い、と感じる性格です。トレーニングは、YouTube や記事で勉強しながら、自分で考えて続けています。勉強したことを試して、結果が数字に出る。その手応えが、続ける理由になっています。

だから、ほしいのは「今日はこれをやりなさい」と決めてくれる相手ではありません。決めるのは自分でいたいのです。ほしいのは、数字の変化に気づかせてくれて、「こういう手もありますよ」といくつか並べてくれる相手です。選んで、試して、結果をまた一緒に見る。その繰り返しを、楽しく続けたいと思いました。

もう一つは、年齢です。50代後半になると、故障や仕事の都合で、練習が途切れることが増えます。数字が落ちる時期は、必ず来ます。そのときに厳しく評価されたら、ダッシュボードを開くのがますます億劫になります。落ちた理由を分かったうえで、「ここからまた積み上げましょう」と言ってくれる相手なら、また開こうと思えます。アバターを励まし役にしたのは、そのためです。

## 3. 課題の整理（表面的になっていないか）

### 3-1. 表に見えている困りごと

Apple Watch での計測は、ここ2、3年続けています。はじめのうちは、その日のワークアウトを1件ずつ見ていました。地図に描かれたルートを、よく眺めていました。

そのあと、少しずつ知識が増えました。一つは、心拍のゾーンを意識して、強度を調整することです。これは、YouTube で知りました。もう一つは、日々のトレーニングの積み重ねを、「体力」と「疲労」という数値で追えることです。こちらは、Intervals.icu で知りました。すると、見たいものが変わってきます。1回ごとの記録ではなく、数週間、数ヶ月の積み重ねとしての傾向です。

ところが、ふだん使っていた Apple のフィットネスとヘルスケアは、1回のワークアウトや、1つの数値を見せることが中心でした。負荷の積み重ねを見る機能も、あります。ただ、結果は「平均より上」のような言葉にまとめられていて、私には、かえって分かりにくく感じました。Intervals.icu なら、積み重ねを見られます。ただ、画面もメニューも多く、私には見づらく感じました。見たい数字にたどり着くまでに、手間がかかります。数字は毎日溜まっているのに、見たい形では、すぐに見られない。だから、ふだんは見なくなりました。

### 3-2. 本当に解決したい課題は何か

- **なぜそれが困る？** → 継続して見ていないと、体に起きている変化に気づけないからです。休めば落ちる。再開すれば戻る。そういう変化は、数字にはっきり出ています。
- **なぜそれが困る？** → 気づけないと、自分で試したことの結果を確かめられないからです。勉強して練習のやり方を変えても、それが効いたのかどうかが分かりません。
- **なぜそれが困る？** → 確かめられないと、トレーニングのいちばん面白い部分を見逃すからです。やったことが、数字になって返ってくる。データは揃っているのに、見に行く手間と、読み解く手間のせいで、それに気づかないままになっています。

→ 本当に解決したい課題：**データは揃っているのに、それを読み解いて、面白い変化に気づかせてくれる相手がいないこと。そのために、自分の体に起きている変化と、次に試せることを、見逃し続けていること。**

「見やすいダッシュボードが欲しい」というのは、手段の話にすぎません。困っているのは、グラフの見た目ではないのです。グラフを前にして、何が起きているのかを言葉にする。その作業を、毎回自分でやらなければならないことです。この作業には知識が要り、手間もかかります。だから後回しになり、やがてやらなくなります。数字を言葉にして、「こういう手もありますよ」と並べるところまでを、誰かが引き受けてくれればいい。そうすれば、残るのは、選ぶことと試すことです。いちばん面白い部分だけが、手元に残ります。

## 4. 想定ユーザーについて

### 4-1. 想定しているユーザー

50代後半の会社員です。平日はデスクワークで、ランニングは平日にも、ロードバイクは週末に続けています。目的は、レースで勝つことではありません。健康のためです。VO2max のような数字を、落とさずに保ちたいと考えています。Apple Watch を着けて2、3年。記録は毎日溜まっています。コーチはいません。YouTube や記事で勉強して、練習のやり方を自分で決めています。ところが、溜まった数字は、ふだん見ていません。トレーニングのあとにその日の記録を眺めることはあっても、数週間、数ヶ月の流れとしては、見ていないのです。

#### 年齢設定

- **年齢**: 40〜60代です。中心は50代です。
- **理由**: 健康のために運動を続ける動機が、はっきりしてくる年代だからです。VO2max と寿命の関係のような話が、自分ごとになります。一方で、若いころより回復に時間がかかります。仕事や体調の都合で、1週間ほど走れないことも、ときどきあります。数字は、上がったり下がったりします。そのたびに「もっと頑張れ」と言われたいわけではありません。何が起きているのかを知って、次にどうするかは自分で選びたい。励ましを前提にして選択肢を並べる、というこのサービスの形が、いちばん合う年代です。

#### 生活・状況設定

- **生活・状況**: 平日はデスクワークです。ランニングは平日にも、ロードバイクは週末にします。年に1、2回は、遠征やイベントに出ます。トレーニングを終えて一息ついたときに、その日の記録を見ます。
- **理由**: その場面で見えるのは、今日の1回ぶんの記録だけです。この数週間の流れの中で、今日がどういう位置にあるのか。疲労がたまってきているのか、体力が積み上がっているのか。それを知るには、別の画面を開いて、自分で読み解く必要があります。loadline では、週に1回、アバターが「振り返り」を用意します。開けば、この数週間の流れを、15秒ほどで話してくれます。そのあとに、その週の過ごし方の選択肢が、2つか3つ並びます。チャートのほうは、記録が届くたびに更新されます。

#### 環境設定

- **環境**: Apple Watch でワークアウトを記録していて、iPhone のヘルスケアにデータが溜まっている人です。loadline は、PC かスマートフォンのブラウザで使います。画面とアバターの声は、英語です。
- **理由**: この環境のハードルは2つあります。1つ目は、ヘルスケアのデータが iPhone の中に閉じていて、ブラウザからは読めないことです。loadline は、iPhone の送信アプリ（Health Auto Export。有料）を橋渡しに使います。設定は最初の1回だけで、そのあとは、記録が自動でサーバーに届きます。2つ目は、言語です。同じ状況の人は、国を問わずにいます。Apple Watch でトレーニングを記録している人は、英語圏のほうがずっと多いので、英語版を先に作ります。アバターのセリフは、短く平易な英語にして、字幕も出します。

## 4-4. ユーザーがサービスを導入して利用するまでのイメージ(導入・継続の流れ)

**知る・思い出すきっかけ**

作り方を、技術記事として公開します。Zenn（日本語）と dev.to（英語）に書く予定です。題材は、「ダッシュボードの前でアバターが話すまで」の作り方です。読むのは開発者ですが、その中には、自分でも走ったり自転車に乗ったりしている人がいます。そこが、最初の入口になります。もう一つは、検索です。「休んだら VO2max が下がった」のような体験を調べた人が、記事にたどり着くことを想定しています。

**最初の一歩（登録・導入）**

1. ゲストログインで、デモデータのダッシュボードを開く。アバターが話すところまで、登録なしで試せます
2. 使うと決めたら Google アカウントでログインして、設定画面で最大心拍、安静時心拍、振り返りを聞く曜日を決める
3. 設定画面で送信用のトークンを発行する
4. iPhone に送信アプリ（Health Auto Export）を入れて、送信先とトークンを設定する。iPhone のヘルスケアで、ワークアウト、心拍数、心肺機能（VO2max のことです）の読み取りを許可する
5. 過去の記録を、期間を指定してまとめて送る

4 には、正直に言って手間があります。送信アプリは有料で、設定する項目もいくつかあります。特に、ヘルスケアの読み取りの許可を忘れると、何も送られません。ここは、画面の案内で、1つずつ確かめながら進められるようにします。設定は最初の1回だけです。そのあとは、iPhone のロックを解除したときに、記録が自動で届きます。送信アプリを開く必要はありません。

5 が終わると、数ヶ月ぶんのチャートが、その場で描かれます。少し待つと、アバターが最初の一言を話します。「この3ヶ月は、こういう流れでしたね」という内容です。溜めるだけだった自分の記録について、初めて誰かが話してくれる。ここが、使い始める瞬間になると考えています。

**利用を続ける理由**

- 週に1回、アバターが新しい振り返りを話します。曜日は、自分で選べます。毎日ではないので、同じ話の繰り返しになりません。
- 選んだ選択肢を、アバターが覚えています。「先週は、軽めにすると決めましたね。疲労が下がってきました」のように、次の週に結果を一緒に確かめます。選んで、試して、確かめる。この繰り返しが、続ける理由になります。
- 1回が短く済みます。話は15秒ほどで、あとは選択肢を1つ選ぶだけです。
- 休んでも、責められません。しばらく走れなかったあとに開くと、アバターは「おかえりなさい」から始めます。記録は自動で届くので、開かない期間があっても、いつでも戻れます。

### 5-2. それでも自分が作りたい理由

既存のサービスは、どれもよくできています。それでも続かなかった理由は、2つあります。

1つは、見せ方です。指標を数多く並べるものは、見るべきものを探して意味を考えるのが、自分の仕事になります。逆に、結果を一言にまとめるものは、なぜそうなのか、どうすればいいのかが、分かりません。私がほしいのは、その中間です。数字を2つか3つ拾って、理由を添えて、「こういう手もありますよ」と選択肢を並べてくれる。決めるのは、こちらに任せてくれる。そういう相手です。

もう1つは、楽しさです。どれも、真面目な道具として作られています。それは正しいのですが、開く楽しみがありません。画面に出るのは、文字とグラフです。声と姿のある相手が話しかけてくるのとは、体験が違います。

### 5-3. 差別化を「体験価値」で表現する

- **私のアプリの差別化ポイント**: 健康のためにランニングや自転車を続けている人が、週のはじめに、アバターからこの数週間の流れを15秒ほどで聞いて、その週の過ごし方を自分で選べる。

たとえば、仕事が忙しくて疲労がたまった週には、アバターはこう話します（実際に試作で生成したセリフです）。

> You pushed through a tough week at work with poor sleep. Your fatigue is up at 68, well above your fitness of 47, so it makes total sense that your legs felt like lead on that climb.
>
> （仕事が大変で、よく眠れない1週間でしたね。疲労は68まで上がっていて、体力の47を大きく超えています。あの登りで脚が鉛のようだったのも、無理はありません。）

そのあとに、「しっかり休む」「軽く流す」「脚をほぐす」という選択肢が並びます。数字は2つだけ。理由は、本人が書いたメモから拾っています。どれを選ぶかは、本人が決めます。選んだ結果は、次の週に、アバターと一緒に確かめます。

アバターは、励ましを前提に話します。「もっと追い込め」とは言いません。痛みや病気の判断にも、踏み込みません。数字が落ちた週にも、開くのが嫌にならない相手であることを、大事にしています。

やさしい言葉づかい、AI への相談、負荷の可視化。1つずつを見れば、すでにあるものです。loadline が違うのは、それらを、声と姿のある1人の相手にまとめたことです。ダッシュボードの前に立って、自分の数字について話してくれる相手がいる。その体験は、調べた範囲では、ほかにありませんでした。

## 6. このサービスで提供したい価値

### 6-1. ユーザーの変化

- **行動の変化**: 週に1回、loadline を開いて、アバターの振り返りを聞くようになります。15秒ほどです。並んだ選択肢から、その週の過ごし方を1つ選び、次の週に、結果を確かめます。数字を探して読み解く手間は、要らなくなります。
- **気持ちの変化**: 数字を見るのが、楽しみになります。数字が落ちた週にも、開くのが嫌になりません。アバターは責めずに、理由と一緒に話してくれるからです。
- **考え方の変化**: 数字を「良い、悪い」で見るのをやめて、「何をしたら、どう変わったか」で見るようになります。休めば落ちる。再開すれば戻る。その関係が分かってくると、次に何を試すかを、自分で考えられるようになります。

### 6-2. 価値を一文で表す

loadline は、Apple Watch に記録を溜めるばかりだった人が、アバターの話を聞くだけで自分の体の変化に気づき、次に試すことを自分で選べるようになるサービスです。

## 7. このアプリで実現すること

MVP では、このサービスの核となる体験だけを作ります。週に1回、アバターが自分の数字について話してくれる。並んだ選択肢から1つを選んで、次の週に結果を確かめる。この体験が成り立つかどうかを、確かめます。それ以外の機能は、本リリースに回します。画面とアバターの声は、英語です。

### MVPで作る機能

| # | 機能 | 内容 |

| 1 | ログイン | Google アカウントでログインします。初めての人は、そのままアカウントが作られます。デモデータが入ったゲストログインも用意します。アバターの振り返りまで、登録なしで試せます。 |
| 2 | 送信用トークンの発行 | 設定画面でトークンを発行し、iPhone の送信アプリに設定します。再発行もできます。 |

| 4 | 設定 | 最大心拍、安静時心拍、強度の境目になる2つの心拍を入力します。タイムゾーンと、振り返りの曜日も選べます。メモを AI に送らない設定もできます。 |

| 10 | 選択肢の記録 | 選んだ選択肢を保存して、次の週の振り返りの材料にします。 |
| 11 | ワークアウト一覧と詳細 | 取り込んだワークアウトを、日付、種目、時間、平均心拍と一緒に一覧で見られます。1回ごとの詳細では、心拍の推移と、強度ごとの時間を見られます。 |

## 8. このアプリの懸念点とその対策

### 懸念点① アバターが、不適切なことを言う

- **何が問題になりそうか**: LLM が書いたセリフが、利用者に無理をさせるおそれがあります。疲れている人に「もっと追い込みましょう」と勧める、痛みについて「心配いりません」と言う、などです。
- **なぜそう思うか**: LLM は毎回違う文を書くので、すべてを事前に確かめることはできません。想定しているのは、回復に時間がかかる年代です。Gemini の規約も、医療的な助言に使うことを禁じています。
- **そのために考えている対策**:
  - 状況の判定はコードで行い、LLM には、それを言葉にすることだけを任せます。
  - セリフは選択肢の形にして、必ず軽い選択肢を入れます。疲労が高いときは、強度を上げる選択肢を出しません。
  - できたセリフは、判断専用の AI（Jev）で確認します。引っかかったら、人が書いた定型のセリフに切り替えます。試作では、危ないセリフをすべて止められました。Jev は英語での精度がいちばん高いので、英語版を先に作ります。

### 懸念点② 外部のサービスに頼っている

- **何が問題になりそうか**: 外部のサービスが1つ止まると、loadline も止まるおそれがあります。頼っているのは、記録の取り込み（Health Auto Export）、セリフの生成（Gemini）、セリフの確認（Jev）の3つです。
- **なぜそう思うか**: 試作の途中で、Gemini が混雑して応答を返さないことが、実際にありました。Jev は、2026年9月に公開されたばかりのサービスです。
- **そのために考えている対策**:
  - どこが止まっても、定型のセリフに切り替えて、サービスは止めません。チャートとメモは、外部の AI なしで動きます。
  - Gemini が混雑しているときは、控えのモデルを試します。振り返りは前もって作る仕組みなので、時間をおいてやり直せます。
  - Jev と送信アプリは、あとから別のものに差し替えられる作りにします。

### 懸念点③ 健康に関するデータを預かる

- **何が問題になりそうか**: 体調について書かれたメモが、漏れたり、意図しない形で使われたりするおそれがあります。loadline はメモを預かり、セリフを作るために外部の AI にも送ります。
- **なぜそう思うか**: 「腰の治療」のような内容は、人に見られたくないものです。運営するのは個人なので、扱い方を最初から決めておく必要があります。
- **そのために考えている対策**:
  - 外部の AI に送るのは、メモの文章と数値だけです。名前やメールアドレスは付けません。学習に使われない方法で呼び出します。
  - 「メモを AI に送らない」設定と、データをすべて消せる機能を用意します。
  - 何をどこに送るのかを、プライバシーポリシーに明記します。利用は18歳以上とし、EU は提供の対象外にします。個人の運営で、EU のデータ保護の規則に対応しきれないためです。

### 懸念点④ 運営の費用が膨らむ

- **何が問題になりそうか**: 利用者が増えると、運営の費用を個人で負担しきれなくなるおそれがあります。セリフの生成と音声の合成に、費用と計算の時間がかかるためです。
- **なぜそう思うか**: 試作で測ると、1回の振り返りを作るのに約25秒かかりました。画面を開くたびに作ると、利用者の数だけ費用が増えます。
- **そのために考えている対策**:
  - アバターが話すのは、週に1回にします。数値は1日ではほとんど動かないので、内容としても合っています。生成の回数は、毎日作る場合の約7分の1です。
  - 生成は、導入のときと、決まった曜日にだけ、サーバーが行います。画面を何度開かれても、費用は増えません。
  - 月ごとの生成の回数に上限を設け、超えたら定型のセリフに切り替えます。

## 9. 今後の展開・発展の方向性

### 観点

- **ユーザーはなぜ使い続ける？**: 週に1回、新しい振り返りがあるからです。先週に選んだことの結果を、アバターと一緒に確かめられます。
- **続けることで何が変わる？**: 数字を「良い、悪い」ではなく、「何をしたら、どう変わったか」で見られるようになります。
- **データが溜まると何ができる？**: 振り返りが、自分の過去と比べたものになります。「去年の夏に1ヶ月休んだあとは、6週間で元に戻りました」のように、アバターが過去の似た時期を引いて話せます。選んだ選択肢と、その後の数字の動きも溜まっていくので、自分に合うやり方が見えてきます。
- **運用・仕組みで価値を出せないか？**: 作り方を、技術記事として公開します。アバター、音声、LLM を組み合わせる方法は、ほかの分野のダッシュボードにも使えます。

### 今考えている発展案

- **機能追加の方向性**: 節目の日にアバターが話す「特別な回」、月のまとめ、日本語版。その先に、過去の自分と比べる振り返りを考えています。
- **UI・体験の改善**: 英語の発音に合わせた口の動き。設定が QR コードで終わる、専用の送信アプリ。
- **機能以外の工夫**: アバターが話す状況の種類と、定型のセリフを、利用者の反応を見ながら増やしていきます。

### 10-1. 使用予定の技術

- **フロントエンド**: React 19、TypeScript 6、Vite 8

- **チャート**: ECharts 6

- **認証**: Firebase Authentication（firebase 12、firebase-admin 7）

- **セリフの生成**: Gemini 3.8 Flash（Vertex AI 経由。google-genai 2.24）
- **セリフの確認**: Jev 1.13（TypeSafe AI。typesafe-sdk 0.7）
- **音声合成**: Kokoro v1.0（オープンソース。kokoro-onnx 0.6）
- **記録の取り込み**: Health Auto Export（iPhone の送信アプリ）
- **ライセンス**: AGPL-3.0

### 10-2. 技術選定の比較検討

| 項目 | 候補 | 採用/不採用 | 理由 |
| --- | --- | --- | --- |
| アバター | three.js + three-vrm | 採用 | VRM は 3D アバターの標準的な形式で、モデルを自作できる。試作で、表示と口の動きを確認ずみ |
| | React Three Fiber | 不採用 | 試作の時点で、最新の React に対応していなかった |
| | 動画のアバターを生成する外部サービス | 不採用 | 生成のたびに料金がかかる |
| 音声合成 | Kokoro | 採用 | 商用で使えるオープンソース。自分のサーバーで動き、回数ごとの料金がかからない。試作で、Cloud Run で動くことを確認ずみ |
| | クラウドの音声合成 API | 不採用 | 回数ごとに料金がかかり、頼る外部サービスが1つ増える |
| | ブラウザ標準の読み上げ | 不採用 | 声の質が、利用者の端末しだいになる |
| セリフの生成 | サーバーから Gemini を呼ぶ | 採用 | 前もって作っておける。送った内容が学習に使われない |
| | ブラウザから LLM を直接呼ぶ | 不採用 | 画面を開いたときにしか作れない。費用を外から増やされるおそれがある |
| セリフの確認 | Jev | 採用 | 文章を書かず、判断だけを返す AI。速くて安い。試作で、危ないセリフをすべて止められた |
| | キーワードの一致 | 不採用 | 試作で、言い回しを変えた危ないセリフを止められなかった |
| DB | Neon（PostgreSQL） | 採用 | 別の個人開発で使った経験がある。使わないときは止まるので、費用を抑えられる |
| | Cloud SQL | 不採用 | 使わなくても、毎月の固定費がかかる |
| デプロイ | Cloud Run + Dockerfile | 採用 | 別の個人開発で運用した経験がある、定番の構成 |
| チャート | ECharts | 採用 | 別の個人開発で使った経験がある |

- **今回チャレンジしたい点**: アバター、音声、LLM を、1つの画面にまとめることです。もう一つは、LLM の出力を安全に扱う仕組みです。判定はコードで行い、セリフは別の AI で確認し、だめなら定型のセリフに切り替えます。
- **不安な点**: アバターのモデルを自作するのは、初めてです。音声の合成は、サーバーの上では1回に約10秒かかります（試作での実測）。前もって作っておく仕組みで、利用者を待たせないようにします。スマートフォンのブラウザで 3D の表示が重くならないかも、実機で確かめる必要があります。

### 10-3. キャッチアップ不足の懸念

土台の部分は、経験のある技術で組みます。初めての技術は、企画の段階で試作して、動くことを確かめました。

| | 技術 |
| --- | --- |
| **経験があるもの** | FastAPI、PostgreSQL（Neon）、Firebase Authentication、Cloud Run と GitHub Actions でのデプロイ、React、ECharts |
| **初めてで、試作ずみのもの** | three.js と VRM のアバター（表示、まばたき、口の動き）、Kokoro の音声合成（Cloud Run の上での動作）、Gemini でのセリフの生成、Jev でのセリフの確認、Health Auto Export からの記録と VO2max の受け取り |
| **初めてで、これから確かめるもの** | Cloud Scheduler と Cloud Tasks、VRoid Studio でのモデルの自作 |

開発は、経験のある土台から進めます。記録の受け取り、負荷の計算、チャートの順です。そのあとに、アバター、セリフの生成と続けます。セリフの生成が遅れた場合は、先に定型のセリフだけでアバターを動かして、LLM による生成をあとから足します。定型のセリフは、もともと必要な部品なので、無駄になりません。
